# 控制器耗时拆分：小实验结果

结论：**二阶方向导数是最大单项耗时，不是哈希验证。**
本实验只定位当前实现的开销，没有修改或优化算法。

## 结果

复用之前两个历史案例，每个实现预热一次，再进行三组交替顺序的配对计时。
12 次正式重放、630 个更新全部通过逐步精确核验，仍分别在第 50、55 步
首次达到 99% 正确率；预测坐标、幅度、参数、评估 logits 和最终优化器状态不变。

下表分母为：两个案例各阶段的三次计时中位数之和，包含评估和核验。
这是同步分段墙钟时间的近似归因，不是未经插桩训练的精确性能占比。

| 分段 | 占已计时分段总和 |
|---|---:|
| 二阶方向导数（嵌套 JVP） | 25.30% |
| 一阶方向导数 | 6.46% |
| 常规训练前向、反向、梯度裁剪和 AdamW 更新合计 | 34.30% |
| CPU/GPU 快照、搬运、转换及缩放写回合计 | 15.15% |
| 正确率评估（含读出与转 CPU） | 7.99% |
| 内外部哈希/比较及最终状态核验 | 2.28% |
| 批量目标边界计算 | 2.47% |
| 其余：设随机种子、清梯度、delta 计算、幅度选择等 | 6.04% |

一阶加二阶合计 **31.77%**；二阶方向导数分别累计约 0.305、0.326 秒，
在两个案例中都是最大单项。三次重复的全部分段时间与调用次数均保留在
`receipts/`；汇总在 `RESULTS.json`。

若把为核验而做的额外参数快照也计入核验，核验合计约 **5.96%**；再把
全部正确率评估计入则约 **13.95%**。这些是重新归类而非额外相加的开销。
正确率评估本身也用于判定首次达标，不能简单作为无用核验删除。

## 计时影响

| 案例 | 不分段的更新中位耗时 | 分段计时版 | 差异 |
|---|---:|---:|---:|
| 481b86f81d58d496a687 | 0.9516 秒 | 0.9746 秒 | +2.42% |
| 786d0a3628f6f791399f | 1.0628 秒 | 1.2518 秒 | +17.78% |

每段强制 GPU 同步、Python 计时和运行波动会影响性能，所以上述占比只用于
识别主要开销，不用于承诺消除某段后会准确加速多少。没有移除核验，没有
改变目标数、竞争者数、二阶项、每五步决策规则或候选幅度。

下一步若要优化，应优先检查导数计算的重复求值及数据搬运；本次未实施。
不能把删除二阶项、少检查目标或省去验证当成等价实现加速。

## 文件和保护范围

- `profile.py`：可检查的分段计时执行和精确重放断言。
- `PROTOCOL.md` / `RUN_SEAL.json`：运行前协议与源文件哈希。
- `RESULTS.json` / `receipts/`：完整计时结果。
- `audit.py` / `AUDIT.json`：独立回读原台账、检查逐步身份和重算汇总。

本机 RTX 4060 Ti 8GB，现有 CUDA Python 环境，无依赖安装或系统设置更改。
