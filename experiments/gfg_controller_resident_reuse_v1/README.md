# 组合工程优化：导数复用、GPU 驻留与快照复用

结论：**本次两个历史案例中，保持逐步结果精确一致，完整核验下总时间减少约 17%–20%。**
这是相对于上一版批量控制器的实现优化，不是一次新的 AdamW 胜负比较。

## 一起完成的改造

1. **导数复用**：嵌套 JVP 同时返回一阶、二阶方向导数，把隐藏状态作为辅助输出
   取回，省去原先独立执行的一次一阶求导。保留全部二阶项，不使用有限差分近似。
2. **参数和实际更新驻留 GPU**：预更新参数、真实 delta、原生更新端点和写回临时量
   使用可复用缓冲区，不再每步先搬到 CPU 算差值再搬回 GPU。
3. **分组批量操作**：按设备和 dtype 分组，使用 foreach copy/sub/mul/add。
   乘法与加法仍为分开的操作；没有切换 AdamW 的 fused/foreach 算法执行路径。
4. **打包与复用快照**：同组参数一次复制到 CPU，再按名字建立视图做原有哈希检查。
   只有 alpha=1 且核验后没有参数修改时，内部核验快照才复用于外部参数核验。
5. **继续使用通用批量边界核心**：目标数量、类别数和隐藏维度从输入获得；
   模型结构相关的隐藏状态获取仍放在 nanoGPT 适配器中。

通用缓冲区、方向导数函数与边界核心可以独立复用，但不声称已经验证其他架构的
适配器或任务效果。CPU 快照在创建后独立，不会被下一次缓冲区复用覆盖。

## 保持不变与检查

- 所有目标和竞争者、四个候选幅度、二阶公式、严格大于零的正确边界、每五步决策。
- AdamW 的参数、状态演化与 `foreach=False, fused=False`；不改变学习率或调度。
- alpha=1 保留原生参数字节，不做减去后再加回的重建。
- 每次决策的坐标哈希、分数与幅度，每步参数哈希和评估 logits，最终优化器及参数身份。
- 完整保留内部非修改核验和外部冻结台账对照，不把删除核验算作性能收益。

20 次正式重放、1,050 个更新全部精确一致。另有四次预热和 CPU/GPU 各三组不同
维度的缓冲区/方向导数测试。额外负对照故意在选择阶段修改参数，仍被
`SELECTOR_MUTATION` 拦截；打包快照的独立性也通过检查。

当前小模型的 PyTorch 峰值已分配显存约 95.65 → 97.57 MiB，增加约 1.91 MiB；
分配器峰值保留显存均为 104 MiB。这不是整台 GPU 的总占用，也不是大模型显存估计。

## 文件与复现

- `engine.py`：通用常驻缓冲区、共享导数计算、nanoGPT 适配器和控制器执行。
- `run.py`：精确重放、交替配对计时与失败记录。
- `PROTOCOL.md` / `verification/RUN_SEAL.json`：预先固定的协议及代码身份。
- `checks.py` / `EXTRA_CHECKS.json`：快照独立性与参数污染负对照。
- `audit.py` / `AUDIT.json`：回读原始台账、逐步身份及统计重算。
